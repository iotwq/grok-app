# 流式输出与输入卡顿修复（2026-09-15）

## 流式输出刷新

实际 MarkdownChat 组件复现：持续每 60 ms、128 ms、250 ms 输入分片时，
短文本、2,100 字符、12,100 字符的回答均可能停留在初始文本。
原实现每次 source 更新都会取消并重新安排解析，是防抖而非定时节流。

现保留首次刷新截止时间，到期绘制最新内容；沿用 110/220/280 ms 的解析间隔，
避免长回答每 token 解析。流结束立即显示完整文本并取消排队刷新，卸载同样清理定时器。

验证：新增三种长度/分片频率的持续增长回归均在修复前失败、修复后通过；
同时覆盖停止输入后的尾部刷新、结束时立即显示和卸载清理。
MarkdownChat、streamRenderPolicy、softStreamBuffer 共 24 项通过，定向 ESLint 通过。

## 验证边界

这次修复针对收到内容之后的显示延迟。既有 CLI 日志中的首 token 等待（约 14–20 秒，
新闻查询某次调用约 60 秒）发生在 UI 渲染之前，无法仅凭本地记录细分服务商、网络与模型计算。
不调整模型、推理强度、网络或凭据。单元测试的模拟时钟用于证明刷新不会被持续分片饿死，
不等同于安装版 WebKit 的帧率或真实模型速度测量。当前已安装的包仍需重新构建才能包含修复。
