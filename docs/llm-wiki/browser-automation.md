# 内置浏览器自动化

Grok App 通过内置 `grok-browser` stdio MCP，把右侧 Resources 浏览器交给本机 Grok Build Agent 操作。官方 Grok（包括 grok-4.6）和自定义主模型均可获得这组工具；是否正确选择和调用仍取决于模型的工具能力。升级后新建或重新连接会话生效。

## 搜索与可见浏览器的选择

| 用户任务 | 默认路径 |
| --- | --- |
| 今日新闻、事实查询、公开资料研究、阅读文章 URL | 当前连接提供的后台 web_search / x_* / web_fetch 或等效检索；不自动展开右侧浏览器 |
| 明确要求打开/展示网页 | 可见浏览器 |
| 填表、点击、已登录网站流程 | 可见浏览器交互，遵守用户已授权范围 |
| 截图、布局检查、网页 UI 验收 | 可见浏览器 |
| 当前连接没有搜索能力或搜索失败 | 说明能力缺口，不擅自打开右侧浏览器，也不偷偷启动无头浏览器；确需交互页时先说明并获得用户同意 |

`grok-4.6` 是模型名称，不是当前中转通道提供后台搜索或 Deep Research 的证明。官方 Grok Build 路由优先使用原生搜索；自定义路由仅使用已暴露的工具。`grok_build_proxy` 需要实际服务端提供并通过已有 `supports_backend_search` 检查；普通 `generic` Responses 中转不会因模型名称自动获得这些能力。Deep Research 只在连接确实提供该能力时使用。

选择规则同时写入本机会话启动规则、MCP 初始化说明和 `browser_open` 工具描述，让模型在工具发现前后都能看到。它是模型行为约束，不是根据中文关键词猜意图的硬拦截；没有新增搜索服务或更改用户中转配置。旧的已运行 Agent 需在更新应用后重新启动会话进程，才能获得新的启动规则。连续页面错误不应反复重开：观察确认一次，仍不可用则报告限制。

## 使用

向 Agent 提出明确的网页任务，例如「用内置浏览器打开这个网址，查看页面，然后填写搜索框」。第一次 `browser_open` 自动展开右侧面板并创建标签，用户可以看到页面、接管操作和关闭标签。每个 MCP 连接拥有一个独立标签，重复 open 在该标签导航；不复用或关闭用户自行打开的浏览器标签。

不需要安装浏览器插件、Node 或 Chromium，也不修改 `~/.grok/config.toml`。应用自身的 `--browser-mcp` 启动分支提供工具，并在 GUI／单实例初始化前运行。浏览器沿用现有内置 WebView 的登录态与下载流程，不读取 Chrome 的个人资料。

| 工具 | 行为 |
| --- | --- |
| `browser_open(url)` | 打开／导航 HTTP(S) 页面并等待加载；也用于关闭后的重新打开 |
| `browser_snapshot(frame?)` | 返回标题、URL、加载状态、正文摘要、当前视口文字、可见交互元素及引用 |
| `browser_click(ref, frame?)` | 点击最近观察到的元素 |
| `browser_fill(ref, text, frame?)` | 替换文本输入框、textarea、contenteditable 的内容，并派发输入事件；不会自动提交 |
| `browser_select(ref, value, frame?)` | 选择下拉框中可用的选项 |
| `browser_scroll(pixels, frame?)` | 纵向滚动页面，随后通过 snapshot 查看新内容 |
| `browser_back()` | 返回上一页，随后通过 snapshot 确认结果 |
| `browser_frames()` | 列出主页面、跨域及嵌套 iframe 的文档 ID 和地址 |
| `browser_screenshot(includeImage?)` | 原生截取当前浏览器视口（含 iframe），返回 PNG 路径和图片 |
| `browser_close()` | 关闭该连接的标签，等待前端关闭生命周期完成 |

快照最多包含 100 个当前视口内的交互元素、16,000 字符的正文摘要和 16,000 字符的视口文字。滚动后可读取摘要之外的可见文字。引用每次快照重新生成；导航、节点被替换、元素语义改变或一次交互完成后，必须重新观察。遮挡、禁用、只读和无效输入均返回工具错误，不假装成功。页面加载超时不表示操作被撤销；点击超时后先观察再决定是否重试，避免重复提交。

## 截图与跨域 iframe（三平台）

三平台使用相同工具和参数，直接控制 Resources 中用户可见的浏览器，无需额外浏览器插件。

| 平台 | 实现与要求 |
| --- | --- |
| macOS | WKWebView 原生截图、独立内容世界及 WKFrameInfo；框架操作需要 macOS 11+ |
| Windows | WebView2 原生框架句柄，Frame7 递归发现嵌套 iframe；通过内置 DevTools 方法捕获视口，不开放调试端口。需要提供 Frame7 的新版 Evergreen WebView2 Runtime，旧运行时会提示更新 |
| Linux | WebKitGTK 4.1 ≥ 2.40：原生视口快照，独立内容世界的全框架脚本通过带回复的原生消息通信；不安装浏览器扩展、不启动额外浏览器 |


- `browser_screenshot` 使用原生 WebView 像素，不通过 DOM 重绘，因此跨域 iframe 和 canvas 等可见内容能进入截图。只截当前视口，不截桌面、其他应用或整页；超过 1600×1600 的图等比例缩小，不放大小图。PNG 保存在 App 数据目录的 `attachments/browser/`，与返回的 MCP `image/png` 图片块内容一致。
- `includeImage: false` 只返回路径／尺寸。已配置为纯文本的自定义模型在连接时自动禁止图片块，避免中转接口拒绝图片；可使用现有辅助识图工具读取路径。切换模型能力配置后重新连接生效。
- 先调用 `browser_frames`，从返回地址选择 `frame` 文档 ID，再调用 `browser_snapshot({frame})` 获取该文档的元素引用。点击、填写、选择及滚动时同时传入同一 `frame`；不传则针对主文档。嵌套跨域 iframe 采用相同操作方式。
- macOS/Linux 的控制脚本与框架注册器位于 WebKit 独立内容世界。Linux 各文档等待一次原生回复唤醒，没有后台定时轮询；页面生命周期负责登记、清理和历史恢复。
- Windows 通过原生 `ICoreWebView2Frame` 执行固定 DOM 脚本；脚本与元素引用位于该文档的页面世界，因此页面可影响返回内容，不能把它当作可信证明。框架引用以文档标记校验，导航后旧 ID 拒绝执行。
- 三平台均不关闭同源保护，也不向网页暴露 Host 命令、token 或任意脚本执行接口；网页本身仍无法读取其他域的 DOM。
- 导航、移除、关闭使旧框架目标失效；每次执行都会校验原生目标和文档 ID，避免落到新文档。历史返回恢复缓存页面时重新登记框架。最多保留 128 个框架注册；脚本无法执行、未加载或浏览器拦截的框架可能不在列表中。
- iframe 快照的坐标、可见元素与滚动基于该框架自身视口；父页面遮挡或裁切应结合主页面截图核对。这仍是 DOM 自动化，不是真实鼠标穿透检测。

## 接入与边界

- 复用现有随机端口 `127.0.0.1` session API 的 Bearer token 校验，新增 `POST /v1/browser/action`；没有新增外部监听或更改认证算法。
- MCP 只接收当前应用进程内的 endpoint，通过环境传递；不从可能陈旧的磁盘 endpoint 推断注入。HTTP 客户端禁用代理和重定向，避免本机 token 被转发。
- 网页端只执行内置的固定 DOM 操作脚本；工具不暴露任意 JavaScript、Tauri IPC、读取本机文件或上传接口。参数经 JSON 编码传入。
- 页面内容是非可信数据，不能授予操作权限。工具仍经过 Grok Build 原有的 MCP 调用与权限流程；工具描述要求发布、购买、删除、改变权限等动作取得用户授权。本实现不新增网站级事务审批系统，也不保证模型能自动判断每一种页面操作的影响。
- 工具在独立阻塞工作线程调用 WebView，保留现有 eval 超时；stdio 顺序执行动作，不阻塞 UI 线程。
- 浏览器依赖主窗口工作台。托盘后台、初始化向导或未挂载工作台时可能无法创建标签，会返回可诊断错误。切换项目使标签卸载时，需要再次 open。
- SSH、WSL、远程 ACP 不注入本机浏览器工具（连接和 MCP 热更新都过滤）；本机可执行文件路径和 loopback 凭据不会因此发给远程 Agent。官方辅助子任务继续沿用不注入 MCP 的现有规则。

## 与 Codex 的范围差异

参考的是“观察页面 → 操作元素 → 再观察”的使用方式，未复制未公开的 Codex 桌面浏览器运行时。当前提供可验证的 DOM 自动化闭环，不等同于完整 Computer Use：

- 已有三平台浏览器视口截图；尚无坐标鼠标／真实键盘输入、桌面 App 控制。
- DOM click/input 不是物理输入；依赖 `isTrusted` 的站点可能需要用户接管。
- 已有三平台跨域及嵌套 iframe 操作；尚不支持 shadow DOM 内部、文件上传、浏览器原生对话框自动化。
- Google 登录等特殊流程沿用现有外部认证窗口，需要用户交互；不可把打开认证窗口误认为登录成功。
- 下载沿用现有保存对话框，不自动代替用户选择路径。
- ChatCut 编辑器的默认系统浏览器交接规则不变。

## 工作区归属（2026-10-04）

内置 MCP 配置携带创建会话的工作目录，浏览器动作传递该归属，执行前由主工作台确认当前可见工作区。前端收到打开/关闭事件时再次检查归属，后台项目不能打开或关闭当前其他项目的标签，也不能抢占侧栏。

当前浏览器仍依赖可见工作台：用户切到别的项目时，后台浏览器动作会明确返回“返回所属项目后继续”，不会偷偷切换项目或等待页面创建超时。工作台无响应的归属检查最多等待 3 秒。此检查是界面路由约束，沿用原有 Bearer 鉴权，不是新增安全边界。

开发冒烟脚本可传第三个参数指定当前项目工作目录；默认使用隔离 App home 下的 `workspaces/general`。本轮自动验证覆盖工作区切换、不抢侧栏、路径分隔符、工具及 Host 浏览器回归；未重新进行三平台 GUI 实测。

## 浏览器导航连续性（2026-10-04）

地址栏提供前进/后退，使用所属 WebView 的真实历史；页面加载或动作提交期间禁用重复操作，执行失败显示错误。页面加载完成时同步地址栏和项目标签状态，切换项目后重新创建 WebView 会打开最后保存的地址。SSH 页面保存远端原始地址，重新挂载时重新建立转发，不把临时本机端口当作远端端口。

该恢复仅保存当前地址，项目切换仍会重建 WebView，不恢复表单输入或原 WebView 的前进/后退历史栈。组件回归使用模拟 Host 覆盖导航、失败提示、地址保存/重建及 SSH 地址映射；未声称完成本轮原生浏览器真机验收。
